# 输入候选重设计：词库扩容与组句候选的移除

2026-11-20。起因：输入 `dangwo` 首页给出「当 党 荡 档 挡 儅 凼」全首音节单字，翻页才见「我」，用户期望首候选是「当我」。

## 1. 诊断

### 1.1 实测（CandidateCount=7）

| 输入 | 首页候选 | consumed |
|---|---|---|
| `dangwo` | 当 党 荡 档 挡 儅 凼 | 全 1 |
| `women` | **我们** 我 握 沃 卧 窝 仴 | 我们=2 |
| `yijing` | **已经** 一 以 意 已 义 议 | 已经=2 |
| `suoyi` | **所以** 所 索 缩 锁 琐 乺 | 所以=2 |

「我们/已经/所以」能出整词，「当我」不能——差别只在词表里有没有那条词。

### 1.2 三层根因

| 层 | 事实 |
|---|---|
| 数据 | 内嵌 starter 只有 222 词（213 个双字词），没有「当我」 |
| 算法 | `engine.go` 的组句候选门槛是 `len(segs) >= 3`，两音节永不组合 |
| 上下文 | `LookupBoost(pinyinKey, word, prevWord)` 的 `prevWord` 只在 `rankTierByUserBoost` 里加权；**候选生成阶段完全不看上下文**。`AIPrompt(raw, appName)` 也不带前文 |

第三层就是用户说的「根据全部输入上下文展示关联能力」——当时基本不存在，只有一层很薄的排序加权。

## 2. 词库扩容

### 2.1 来源与取舍

取 [rime-ice](https://github.com/iDvel/rime-ice)（Apache-2.0）的 `cn_dicts/base.dict.yaml`，54 万词条、带词频。

**必须设权重上限**：该词库含彩蛋词条，按权重取前 N 会把它们顶到首页——

| 词 | 权重 |
|---|---|
| 江泽民同志 | 19260817 |
| 江泽民 | 19260817 |
| 三国群英传 | 12345678 |

选取规则：纯汉字词 + `20000 <= 权重 < 600000` → **45921 词**。

覆盖率验证（198 个日常词）：**197 个命中**。唯一缺失的是「社会」（权重 9999）。把下限降到 9000 可覆盖它，但词数涨到 88269、clvdict 涨到 5.42MB——为一条词多背 2.6MB 不值得。

### 2.2 产物

| 项 | 值 |
|---|---|
| 源 | rime-ice `cn_dicts/base.dict.yaml`，Apache-2.0 |
| 词条 | 45921 |
| 编译后 | `data/common.clvdict` 2.77MB（已编译形态，启动零解析） |
| 校验 | `data/common.meta.json` + 代码内 `commonClvDigest`，不匹配 panic |
| 二进制增量 | +2.8MB（24.9 → 27.7MB 裸二进制） |

嵌入的是**编译后的 clvdict**而非 `.dict.yaml`：解析 4.6 万条要 1.3 秒，冷启动不可接受。

### 2.3 层次

```text
defaultDictionary()
  = ChainDictionaries(StarterDictionary(), commonDictionary(), UnihanDictionary())
                        222 精选词            45921 通用词           单字兜底
```

## 3. 移除「组句候选」

### 3.1 它是什么

词表只有 222 词时的权宜之计：对多音节输入，每个位置取最长匹配词，拼成整句候选。

### 3.2 为什么必须删

词库变大后它的缺陷暴露：**拼接必然产出语义怪词**。

| 输入 | 拼接结果 | 真相 |
|---|---|---|
| `woshiyeshugen` | 我始终国人 | 「我始终」是 `wo'shi'zhong` 的真词，被拼到 `wo'shi'ye'shu'gen` 上 |
| `yeshugen` | 页数根 | `ye'shu`（页数）是真词，加 `gen` 成「页数根」 |

这两条不是估算误差，是**算法语义错误**：词条的拼音切分必须与原输入逐位对齐，跨段拼接做不到。

### 3.3 删后

候选只有三类：**整串词条 → 前缀词条（长者优先）→ 单字**。

对比：

| 输入 | 有组句候选 | 无组句候选 |
|---|---|---|
| `dangwo` | 当我 | 当我 |
| `woshizhongguoren` | 我始终国人(5) 怪拼 | 我始终(3) 我是(2) 我市(2) 全是真词 |
| `yeshugen` | 页数根 怪拼 | 页数(2) 也说(2) 全是真词 |
| `zhonghuarenmingongheguo` | 中华人民共和国(7) | 中华人民共和国(7)（走整串词条） |

另加**首页按覆盖度稳定排序**：避免只覆盖 2/5 音节的前缀词（「我始终」）压过覆盖更多音节的候选。

### 3.4 这意味着什么

A1 决策（整句候选提到首页第 2 位）**被本次修正覆盖**。A1 的前提是「词库只有 222 词，组句候选是唯一能触及后续音节的手段」；前提消失，手段就该撤。整句输入现在靠**整串词条**（「中华人民共和国」走这条）或 AI 候选。

## 4. 连带修正

| 问题 | 修法 |
|---|---|
| `candidate_style.go` 的 cjk/latin 估算 16/9 高估 15pt 字形（实际 14.9px），虚高让 `waterFillCap` 以为 2 字候选放得下 | 改为 15/9 |
| `custom-largest`（22pt × 9 候选 × 横向）在 448px 内数学上放不下 | 测试允许截断，但要求不出面板 |

## 6. 未做（下一批）

| 项 | 说明 |
|---|---|
| C3 上下文参与**生成** | `ime_bigrams` 表已有数据、`LearningWriter` 已在记录，但只用于排序。要用它生成 bigram 候选 |

## 7. 已知风险

- 词库变大后**首页质量不一定更好**：搜狗被用户卸载的抱怨正是「常见字不在首页」。下一批应做首页质量回归（20 个高频词断言 ≥18 正确），目前只锁了 14 个。
- 权重区间是启发式，不是语义筛选，所以出现了「遗精」这类词。
